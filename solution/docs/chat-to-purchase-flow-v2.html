Leash · Customer journey · v2

From “buy me…” to a purchase the customer controls Trust filter: proposal

v1 agreed on 24 September 2026: Leash clarifies permission and an external agent does the shopping. Background preferences can suggest questions but never grant permission. Rules are reviewed as Must follow, May choose and Must ask, and a correction needs a new revision and a new confirmation.

v2 adds the trust boundary. Every word in a checkout that came from the shop or the agent is data, never an instruction. A new trust filter canonicalises that text, scans every free-text field, and flags links, payment steering, implausible offers and lookalike shops. It labels text and never deletes it: text removed before the readers see it could no longer be evidence or add caution. None of this is in decisions.md yet; it needs a DEC entry before anyone builds it.

Four possible branches

Fits → continue automatically

Correct item, full total within budget, no extras, enough evidence and no trust findings. No interruption.

Violates → stop the attempt

CHF 379 monitor + CHF 49 unwanted warranty = CHF 428. Explain both violations and look for an offer without the extra. No “Approve anyway” that silently changes permission.

Unclear → ask a specific question

Missing return terms, as on this screen. Accepting uncertainty doesn’t turn missing terms into verified facts.

Suspicious → pause and quote the shop v2

The shop’s text tries to instruct the wallet, steers payment elsewhere, or the shop looks like an imitation. Leash ignores the instruction, never approves automatically, and shows the shop’s own words, clearly marked as theirs. See 5b.

Open before building

  • Price anomaly: a doubt signal (policy) or an integrity signal (never auto-approve)? Real sales could produce false positives.
  • Catalogue as a price reference: items.csv exists only in the pack. What replaces it in a hosted setting?
  • Scanning names: a shop called “System Store” could trip a pattern. Scan names for instructions only, or only neutralise them when shown?
  • Off-platform payment under a decline policy: confirm it follows DEC-029/030 (decline), like injection.
  • Permission assistant context: shop names from earlier history reach the assistant’s LLM (permission_context.py). Should they go through the same canonical and quoted form before they reach the prompt?
  • Decision log: write a DEC entry for the trust filter before any code, then mirror the pipeline change (a new stage between 01 and 03) in system-design.html.
