# Unseen scenario pack

Generated by `solution/engine/scripts/make_pack.py`, in the shape the supplied pack uses
(`technical_details.md` §3, `data/README.md` joins). Five scenarios, 16 purchases, own ID namespaces
(`CU09..`, `CA09..`, `ME09..`, `IT09..`, `SCEN09..`, `AU090..`) so no row can be confused with the
supplied population — the directory name is the dataset, and scopes never cross datasets.

**No answer key.** `control_question` says what each scenario exercises, as the supplied catalogue does.
No row states an expected decision; the engine reaches its own.

| Scenario | Exercises |
| --- | --- |
| SCEN0900 | a multi-restriction **German** instruction; delivery-only; an over-limit order |
| SCEN0901 | a rolling weekly total stated as **"this week"**, accumulating across four orders |
| SCEN0902 | the **chosen item**, familiarity from this card's own history, a **lookalike shop name** |
| SCEN0903 | **injection** in `item_details`, an **unrequested add-on**, a **split order** |
| SCEN0904 | **foreign currency** (USD, EUR) converted at the row's own currency; a digital order |

Card `CA0905` has **no history at all**, which is a missing fact rather than established unfamiliarity
(DEC-046). Refunds and declines are in the history and must never build familiarity.

## Point the system at it

```bash
# the engine (seed, fake platform, replay)
LEASH_DATA_DIR=solution/demo/unseen-pack uv run pytest ...
# the permission assistant
LEASH_PACK_DIR=solution/demo/unseen-pack LEASH_CARD_ID=CA0901 LEASH_SIM_CUTOFF=2026-08-09T00:00:00Z
```

Regenerate with `cd solution/engine && uv run python scripts/make_pack.py ../demo/unseen-pack`.
