S5 · Reporting & policy learning
Strength: the card is the leash — revocation is a concept users already own, and the data model maps to it almost 1:1. Cost: policies scoped per-card, so global rules need a separate “applies to all cards” layer.
1dData board — which Viseca entity feeds which screen (reference, not a screen)
viseca.drawio → wireframe surfaces
customers · accounts
per_transaction_limit_chf, monthly_limit_chf, base_currency → hard ceilings the user's policy can only tighten, never exceed. budget_style seeds the default template (strict / balanced / relaxed).
cards
virtual_card, online_enabled, international_enabled, card_purpose, status, expires_on → the toggles on the mission-card screen; status drives the kill switch.
scenario_authorities
authority_id, valid_from / valid_until, initial_status → the policy object itself: one authority per active leash, revocation = status change, expiry = auto-off.
purchase_attempts (+ items)
amount, billing_amount_chf, items_subtotal, delivery_fee, spend_in_period_before_chf, recent_attempt_count_10m, related_authorization_id, purchase_description → the step-up screen's price breakdown, the rolling-limit bar, retry/duplicate suppression. purchase_description and item_details are untrusted: rendered in a quarantine block, never fed to the decision engine.
merchants
merchant_category, merchant_mcc, merchant_country, recurring_capable, availability → whitelist / category blocks / geo rules and the “merchant ok” evidence chip.
authorization_history
status, initiator_type, approved_spend_before_chf, approved_merchant_transaction_count_before, last_approved_at → the log, the merchant-familiarity signal (“12 past purchases”), and the monthly report.
scenario_catalogue · fx_rates
control_question / control_theme → demo scenario picker for the judging walkthrough. fx_rates → “CHF 208 (EUR 219)” conversion line on any non-CHF attempt.
Three decisions render identically across all directions: APPROVE = silent, log only · DECLINE = notification + reason + one recovery action · STEP_UP = timed, two-choice, evidence-first. Never more than two primary buttons in a step-up.
